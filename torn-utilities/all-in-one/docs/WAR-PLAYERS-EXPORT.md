# War Organizer player controls and export

Removed the keyboard-height two-column rule that placed search inside an undersized nested grid. The search row retains its normal width at short heights and stacks on very narrow widths. Hide controls now collapses faction cards, navigation tabs, search, status/FF filters, counts and routine footer status; Show controls remains available, along with the spreadsheet export. Existing collapse state, queries, filters and list-position persistence are reused.

Export both factions (.csv) is at the bottom of the player-list footer. It refreshes both rosters, exports every member regardless of current search/filters/view side, and orders numeric BS estimates greatest to least with unknowns last. Columns include faction side/name/ID, player name/ID, level, fractional days since last activity (2 decimals), and the full numeric BS estimate. Missing activity or BS is explicitly Unknown. Last activity comes from the roster API timestamp rather than relative text or guessed online status. UTF-8 BOM and CSV quoting support spreadsheets; text that resembles a spreadsheet formula is neutralized.

Estimate retrieval reuses the existing selected-key FFScouter service and its cache, consent and request pacing; no Full Access key or new external service is introduced. Estimates are never persisted into roster state. Disabled/unavailable providers produce Unknown values. Incomplete fresh rosters or changed account/faction/estimate scope stop the download. No messages, attacks, reservations or shared-data writes are triggered. The download reuses TU’s Blob/link pattern; actual PDA file handling needs user verification.

The explicit unified-script size guard increases from 1.46 MB to 1.47 MB to accommodate the export and keyboard-layout changes (approximately 6 KB growth). Functional tests remain intact. Production is unchanged.

Validation: build, full regression suite, final War Organizer navigation/scouter/export checks, generated-script syntax and DEV alias/snapshot comparisons passed. Export tests include full unfiltered membership, numeric ordering, activity days, Unknown values, CSV formula neutralization, incomplete roster rejection and selected-key scope changes. Chromium layout rendering stalled in this environment and was stopped; real PDA keyboard geometry and file download handling are unverified.

## 0.5.42.144-dev — filtered Excel workbook

A BS abbreviated column sits immediately after the full numeric BS estimate. Values use two decimal places with K/M/B/T/Qa/Qi suffixes and promote a unit when rounding reaches 1000 (for example 999995 becomes 1.00M). No formulas, macros, external relationships or downloaded libraries are included.

## 0.5.42.145-dev — binary-safe download transport

The supplied .xlsx had an invalid central-directory offset because binary ZIP headers were passed through UTF-8 replacement decoding and re-encoding. Rebuilding the stored archive from its intact XML and applying that text round trip reproduced the uploaded bytes exactly. The content itself contained 140 player rows and the correct A1:I141 filter. The precise host stage causing the conversion was not directly observed.

The export now uses an ASCII base64 data URL with the XLSX MIME type rather than a Blob URL, avoiding a binary-to-text conversion along the download path. Workbook content, filters, abbreviations and sorting are unchanged. The UI download test rejects Blob use, simulates UTF-8 text transport of the URL, then decodes and validates the workbook. The original damaged attachment was locally repaired from intact XML, normalized with openpyxl and checked for identical cell values/types and preserved filters. No player data is committed or sent to another service. Actual PDA/Drive handling still requires device verification.
