# Architecture specification

Core: launcher, navigation, consent, API credential vault, server verification, module registry, storage, diagnostics.

Adapters: Tampermonkey and Torn PDA. Shared feature interfaces must have platform-specific implementations and feature detection.

Modules: separate source folders, explicit manifest, factory registration, lazy activation, deactivation, namespaced storage and scoped DOM styling. One module error must not prevent the Manager from starting.

Build: deterministic packaging with immutable build ID and manifest, source map where feasible, validation and regression tests. Build artifacts should be generated by CI rather than hand-edited.

Diagnostic rescue tool: independent userscript to inspect runtime availability even if TU Manager cannot open. No API key collection.

Security: server-verification remains authoritative; avoid storing raw keys in diagnostic logs. Minimize server credential retention and require secure transport. Torn API capability checks must follow actual permissions and module needs.
