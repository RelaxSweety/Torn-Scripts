# Native inventory refresh investigation — DEV .99

TU 0.5.42.99-dev / Item Monitor 1.12.49-dev adds two controls inside the existing Temporary DEV Diagnostics. It does not restore the removed Direct Item Tools section or automatic page refresh.

- **Inspect Native Inventory Refresh** reads the own-property descriptor for `loadEquippedItems` in the page realm. It never invokes the function or an accessor. The report contains bounded function structure with string/template literals, comments and numeric values omitted, plus up to 60 same-origin `/js/` or `/builds/` script paths with queries removed. Four inspections maximum are retained in memory for the current page. Export before navigating; run inspection again on another page if needed. A missing function is useful evidence, not a successful refresh.
- **Add 1 A+ Blood Bag to Travel Inventory** moves one item ID 732 into carried travel inventory, without consuming it or equipping gear. Each trusted click requires active diagnostics, TU authorization, visible/focused Torn Travel Agency, no flight panel, no active Snatch and Run, fresh non-travel profile (Okay/Hospital/Jail), unchanged account across a second profile check, a complete fresh inventory and an empty slot. It sends one `POST /page.php?sid=travelData&step=addSlotItem` with JSON `{itemID:732}` using Torn's signed-in website session. No API key is sent to this endpoint.
- Success requires Torn's success response plus a fresh complete inventory showing exactly one formerly empty slot containing 732, identical capacities and every other item/slot unchanged. An uncertain result leaves the existing persistent per-tab item-attempt lock set, shared with integrated use/trash/purchase handlers. There is no automatic retry. **Review Unresolved Item Attempt** requires the user to verify native inventory and acknowledge before unlocking. Clear Logs does not unlock an uncertain action.
