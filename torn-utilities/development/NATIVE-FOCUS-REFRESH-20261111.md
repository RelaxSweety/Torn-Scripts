# Manual native inventory refresh test — DEV .100

TU 0.5.42.100-dev / Item Monitor 1.12.50-dev adds **Test Native Inventory Refresh** to the existing Temporary DEV Diagnostics. This is a manual investigation control, not an automatic purchase step. The removed standalone Direct Item Tools section and automatic page reload remain removed.

The previous .99 PDA report confirmed two separate itemID 732 additions: server inventory increased from zero to two A+ bags in 18 slots. POST plus verification took 456 ms and 466 ms, excluding preliminary status/inventory guards. The report found no own `loadEquippedItems` function on the Travel Agency page but identified the current first-party travel bundles. Reviewing those public bundles showed RTK Query `inventory` tag invalidation in native add/buy mutations, `refetchOnFocus:true`, listener setup on the travel store, and a window focus listener dispatching the focused action without a trusted-event requirement. An isolated test of the extracted listener confirmed a synthetic focus event reaches that action. None of this yet proves real PDA inventory redraw.

The new button requires a trusted click, active diagnostics, visible/focused authorized Torn page, matching page document, native travel root, no unresolved item attempt and no active Snatch and Run. It dispatches exactly one `focus` event in the page realm. It sends no direct request, invokes no inspected function, changes no inventory cells and performs no navigation, item use, purchase or automatic retry. Torn may respond by refetching other subscribed read-only data as well as inventory.

For five seconds it observes the existing passive recorder's small request summaries and native inventory-slot snapshots. The report includes GET inventory status/duration, other read count, before/after numeric slot and image-item identities, first observed cell-change timing, elapsed observation time and a bounded result history. It excludes labels, image URLs/queries, tokens, credentials, arbitrary HTML and raw responses. Outcomes distinguish completed inventory read plus cell changes, read with unchanged cells, cell change without an inventory read, no observed inventory read, cancellation and unavailable dispatch. These are temporal observations; unrelated native updates can coincide. The test can therefore record evidence without claiming synchronization from a GET alone. A negative five-second result does not prove the listener can never respond.

Stopping diagnostics, clearing logs, leaving the page, losing focus/authorization, or starting an active run cancels observation and cleans up timers/listeners. Integrated item actions cannot overlap this explicitly requested observation. No departure lock is introduced and the test is blocked during an active Snatch run. Results are in memory for the current page, maximum four tests; export before navigating.

Real-device procedure: update to .100, go to the Travel Agency in Torn with one spare A+ bag and an empty carried slot, open Item Monitor, add one bag with the existing POST test, click **Test Native Inventory Refresh**, wait for the five-second result, check whether the actual bag image appeared, then **Report Generation** before navigating. Do not repeat an uncertain item-add action. Actual PDA/desktop native redraw remains unverified until this procedure is reported.
