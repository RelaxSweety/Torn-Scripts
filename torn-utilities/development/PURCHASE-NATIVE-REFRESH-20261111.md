# Non-blocking native inventory refresh — DEV .101

TU 0.5.42.101-dev / Item Monitor 1.12.51-dev sends one page-realm window focus event after each freshly verified direct purchase. It does not wait for Torn's refresh requests, add a timer, reload/navigate the page, or gate the next remainder click/departure. Failure to dispatch is best effort and cannot convert a confirmed purchase into an uncertain purchase or block Return. No refresh is dispatched for rejected, unconfirmed or uncertain purchases, restored purchase state alone, or completion without a new transaction.

The native cache mechanism was validated by the .100 real PDA Travel Agency report: the event was followed by a native inventory GET starting in 5 ms, completing in 711 ms, then slot 1 changing from empty to an image for itemID 732 at the first 801 ms sample. The other 17 cells remained empty. Torn's travel bundles enable refresh-on-focus for subscribed native queries. The same event after foreign purchases is now implemented, but live foreign-market acceptance remains to be reported. Other native subscribed reads may refresh alongside inventory. TU does not fabricate native item controls or infer purchase quantity from the redraw; existing server inventory verification remains authoritative.

Removed the **Native inventory refresh investigation** section, explanatory paragraphs and Inspect/Add A+ bag/Test Refresh buttons from Item Monitor. Existing Temporary DEV Diagnostics activation, stop, report and clear controls remain. The general unresolved-item-attempt review control remains accessible for safe recovery from ambiguous use/trash/purchase results. Existing passive request and native DOM monitoring supplies follow-up evidence; no five-second diagnostic observation is started by purchase refresh.

Preserved: three-second noninteractive purchase notifications, verified green check/red X slot indicators, cumulative quantity/capacity proof, one initial plus five additional click-dependent purchase attempts, immediate departure choices/Return, no automatic page reload, per-item alerts and native countdown synchronization.

Validation: `npm run build` (965612 bytes), full `npm test`, focused direct-purchase/native-focus regressions, trusted Chromium purchase fixtures and full-bundle UI-removal fixtures. Unit regressions assert one event per confirmed transaction, none for uncertain outcomes, and immediate successful return even if refresh dispatch throws. Browser fixtures use a focus listener returning an unresolved promise to demonstrate the purchase/return path does not await asynchronous refresh work. They retain initial plus five remainder quantities, successful/partial/exhausted outcomes, rejected synthetic clicks, no reload, notifications/badges and uncertain-result locks. All gameplay is mocked; no real item movement, purchase or tester-data deletion is performed.
