This agreement does not authorize anything Torn prohibits and does not override Torn's rules. Stop using a feature if Torn staff instruct you to do so.

TU must use API keys only for the purposes disclosed here. Material changes to those purposes, recipients, or access requirements must be disclosed before the changed use begins.

## 2. API keys and access

TU never asks for your Torn password. Obtain your API key directly from Torn and use the least access needed for the features you choose. TU currently accepts **Public Only or Limited Access** keys for registration; it does not require or accept Full Access keys for registration. Acceptance of a Limited Access key is not permission to retrieve every selection that key can access.

TU verifies the key's access level and account owner. You should not need to provide your name or player ID separately for verification. TU may retain your verified Torn name and ID as described below.

The public Torn API is read-only. TU uses it to retrieve information. A Snatch and Run item-use action instead uses your signed-in Torn website session and Torn's security token; it is not an API-key-authorized gameplay mutation.

## 3. Local storage and key security

TU currently stores saved API keys in Torn-origin browser storage without encryption. Some environments also support userscript-manager storage. Other scripts running on Torn pages may be able to read Torn-origin storage; TU does not represent it as an isolated credential vault.

Do not publish your API key or session token in a screenshot, diagnostic report, repository issue or message. Remove a saved key through TU's key controls and revoke or replace it through Torn if you no longer want TU to use it or suspect exposure. Removing a browser key does not automatically delete records already stored remotely.

TU and its operators must protect keys and API-derived information, limit access to authorized purposes, and not sell, publish, or repurpose your key or private API data beyond the disclosures and permissions you have given. An agreement acceptance is not blanket permission for unrelated uses.

## 4. Snatch and Run and user actions

Snatch and Run may monitor visible stock, calculate quantities, update clocks, sound alerts, verify inventory and process action results automatically. An alert or stock change does not authorize TU to consume an item, destroy an item, buy stock, or book travel automatically.

The active action button identifies the action you request. Direct item use consumes one selected supported item per press. Native multi-step actions display the next required step and require another user press for the next Torn control click. An additional item destruction or purchase transaction requires its own user action. Execution does not require a second TU popup merely to acknowledge the same requested action.

Item destruction requires acceptance of its separate setup warning and selection of the items to destroy. Actual destruction is permanent. An uncertain submitted action must not be automatically retried. Do not assume an action succeeded or failed solely because a message, countdown or network request was delayed; check Torn's result.

After a confirmed purchase leaves inventory space, TU offers a choice: depart using the step-by-step return flow, or close Snatch and Run and make additional purchases and travel arrangements manually.

These statements describe TU's intended action boundaries. They do not establish Torn approval for every included feature. Chat Archiver's history-loading behavior and other modules must separately comply with Torn's scripting rules.

## 5. Optional reporting and external services

Foreign-stock reporting is optional and off by default. When enabled on a supported visible shop, it sends item identifiers, quantities, prices, country and observation times to TU's service. The reporting payload does not include your Torn player name, player ID or API key. Network metadata can still be processed by the service and its hosting provider. Pending reports may be queued locally and retried; disabling reporting stops further automatic delivery while disabled.

TU uses these services for the stated purposes:

- **Torn:** API data, identity/key verification and user-requested website actions. [API terms](https://www.torn.com/api.html) · [Rules](https://wiki.torn.com/wiki/Rules).
- **Cloudflare:** hosting, request processing and TU service/database infrastructure. [Terms](https://www.cloudflare.com/terms/) · [Privacy policy](https://www.cloudflare.com/privacypolicy/).
- **GitHub:** TU script distribution, updates and published agreement files. [Terms](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service) · [Privacy statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).
- **YATA:** TU's backend may retrieve publicly supplied travel-stock information to supplement observations and estimates. This integration does not require sending your TU registration key to YATA. [YATA website](https://yata.yt/). Its applicable terms and source-data conditions must be linked in the published disclosure before release.

Providers may process IP addresses, request timing, browser/platform information and operational logs under their policies. Stock reports, forecasts and market information may be delayed or inaccurate; forecasts do not guarantee stock or profit.

## 6. Retention, deletion and your choices

You can decline this agreement, disable optional reporting, stop TU modules, remove stored keys, clear TU/browser storage, and uninstall the script. TU features requiring verification and agreement acceptance will not operate if you decline.

Persistent local storage may survive closing Torn. Session storage may survive navigation or browser session restoration. Exported copies are not removed by uninstalling TU. TU cannot remove a copy you have already shared with another recipient from that recipient's systems.

Remote identity, agreement, security, game and stock records are not automatically erased by uninstalling TU, clearing browser storage or revoking a Torn key. Where no retention period or deletion mechanism has been specified above, assume those records may remain indefinitely. Session expiration prevents continued use of that session; it does not itself establish deletion of historical records or backups.

Do not post credentials or private data in public repository issues. Any deletion limits, retained security records and backup retention must be explained when responding to a request; this draft does not promise an unimplemented automatic account-deletion service.

Using extra keys or servers does not authorize bypassing applicable limits. Other tools using your account also contribute to its quota.
